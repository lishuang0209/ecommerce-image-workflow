# 风格处理与扩图：重复提交保护

范围：`/api/demo/ecommerce-style` 和 `/api/demo/ecommerce-resize` 的 `expand` 模式。不包含视频提交或其他生成入口。

- 以项目、操作、原图 ID、风格／比例组成唯一任务；同一进程内共享正在执行的结果，其他进程用 SQLite 事务阻止重复执行。
- 任务登记在已有的 `project_workflow_state` 表中，类型为 `ecommerce-paid-generation`。不新增数据库服务。
- 仅准备阶段可在 5 分钟后重新领取；真正发起上游请求前先持久化 `submitting`。提交后不按时间自动解锁，重启也不解锁。
- 成功后复用已保存且可读取的素材；查询不受素材列表 500 条上限影响。用户删除成功结果后可重新生成。
- 本地校验失败或上游明确拒绝可重试；超时、断线、下载／保存失败进入 `needs_review`，返回 HTTP 409 和 `PAID_JOB_REVIEW_REQUIRED`。另一进程正在执行时返回 `PAID_JOB_PENDING`。
- 已保存素材但完成登记中断时，下次请求会找回素材并修复任务登记。素材登记存在但文件丢失时不自动重新付费生成。

## 未确定结果的处理

目前没有自动查询远端任务、自动下载补偿或人工解锁界面。遇到待核对提示，应先检查服务商记录和本地结果；不要通过删除数据库任务行盲目重试。只有确认原请求未被接收或已终止，才可由维护者针对该任务处理。若远端不支持幂等键，本地无法保证网络中断后的远端“恰好执行一次”，因此默认阻止再次提交。
